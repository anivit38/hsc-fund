# Deploying HSC Endowment

Two pieces, deployed separately:

- **Backend** (`src/server/*`) — an Express API on **Render**. It holds the
  database (a JSON file), runs the risk engine, the scheduled fills/NAV jobs,
  and pulls live prices from Yahoo Finance.
- **Frontend** (`src/*.jsx`, `src/pages`, `src/components`) — a static React
  build on **Firebase Hosting**. It only ever talks to the backend over HTTPS.

Do the backend first — the frontend needs its URL.

## 1. Backend on Render

1. Push this repo to GitHub (see "Git" below if you haven't yet).
2. Go to [dashboard.render.com](https://dashboard.render.com) → **New** →
   **Blueprint** → connect the repo. Render reads `render.yaml` in this repo
   and proposes a `hsc-fund-api` web service. Click **Apply**.
   - No GitHub repo yet? **New** → **Web Service** → connect the repo → set
     **Build Command** `npm install`, **Start Command** `npm run server`,
     **Health Check Path** `/api/health`, then add the env vars from
     `render.yaml` by hand.
3. `JWT_SECRET` is auto-generated by the blueprint. Leave it — don't reuse the
   default from `.env.example`.
4. Leave `CORS_ORIGIN` blank for now; you'll fill it in after step 2 once you
   know your Firebase URL (an empty value allows any origin, which is fine
   for getting started but tighten it once you have the real URL).
5. **Persistent disk**: `render.yaml` requests a 1GB disk, which needs a paid
   Render plan. On the **free** tier, remove the `disk:` block (or Render will
   ask you to upgrade) — the fund still runs fine, but its history resets
   whenever the free instance restarts or redeploys (Render free services also
   spin down after ~15 min idle; the first request after that takes a few
   seconds to wake up and re-seed). For a club that's actually tracking a fund
   over a term, the small paid plan + disk is worth it.
6. Deploy. Once it's live, note the URL — something like
   `https://hsc-fund-api.onrender.com`. Check it:
   ```
   curl https://hsc-fund-api.onrender.com/api/health
   ```
   You should see `{"ok":true,...}`.

## 2. Frontend on Firebase Hosting

1. Install the CLI once: `npm install -g firebase-tools`
2. `firebase login`
3. Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
   (Hosting only — you don't need any other Firebase product for this app).
4. Put its Project ID into `.firebaserc` in this repo (replace
   `REPLACE-WITH-YOUR-FIREBASE-PROJECT-ID`), or run `firebase use --add` and
   pick it interactively.
5. Point the build at your Render API:
   ```
   echo "VITE_API_URL=https://hsc-fund-api.onrender.com" > .env.production
   ```
6. Build and deploy:
   ```
   npm install
   npm run build
   firebase deploy --only hosting
   ```
7. Firebase prints your live URL (`https://<project-id>.web.app`). Go back to
   Render → your service → Environment → set `CORS_ORIGIN` to that URL (and
   the `.firebaseapp.com` one, comma-separated) → save (Render redeploys
   automatically).

You now have a live site talking to a live API that's pulling real Yahoo
Finance prices for every listed security in the fund.

## 3. First login

Self-signup is open — anyone can create an account from the sign-in screen
with any email. One reserved address auto-provisions as CIO the instant it
signs up (`AUTO_CIO_EMAILS` env var on the Render service, defaulting to
`039443@hsc.on.ca`); sign up with that address first to get your first CIO.

Everyone else who signs up lands as an Analyst but sees a "pending approval"
screen and can't read or do anything until the CIO approves them from
**Members** — that's enforced server-side, not just hidden in the UI. The CIO
can also add people directly from that same screen (pre-approved, any role),
or reset a forgotten password.

Every seeded demo member (`alex.chen@school.edu.au` and friends — see
`src/server/universe.js`) still works too, password `welcome2026`. Everyone
should change their password from **Account settings** after first login.

## Local development

```
npm install
cp .env.example .env        # then edit VITE_API_URL if needed
npm run server               # backend on :8080 (auto-restarts on file changes)
npm run dev                  # frontend on :5173, in a second terminal
npm run test:security        # runs the RLS/permission attack suite + a full pitch→fill→NAV cycle
```

## What "live" means here

Every security priced `pricing: "market"` (every listed stock, ETF, bond fund,
commodity fund and crypto ETF in the universe) gets its daily open/close from
Yahoo Finance's public chart endpoint — no API key or account needed. The
backend refreshes this every 15 minutes and also on the first request after
waking from an idle sleep. Securities priced `pricing: "appraisal"` (the direct
real-estate and private-market holdings) have no public feed — exactly like
the real thing — and are valued once a month by the built-in simulator, the
same way a real fund would carry a property at its last valuation.

If Yahoo is unreachable (rate-limited, offline, a symbol it doesn't recognise)
the affected ticker falls back to the deterministic simulator automatically —
the fund keeps running either way.
